# Сервер видео-квиза

Node.js 24+, `npm install`, `npm start`. Адрес: http://127.0.0.1:4173. SQLite, сессии и загрузки хранятся в `data/`, папка исключена из Git. Пароль кабинета автоматически создаётся в `data/admin-password.txt` с правами 600; не публикуйте этот файл. Для постоянного окружения задайте длинный `ADMIN_PASSWORD` через защищённое окружение. Перезапуск с новой переменной меняет пароль.

При первом запуске публикуется `content/quiz.json`; дальнейшее редактирование исходного JSON не заменяет версии в БД. Редактор сохраняет отдельный черновик, публикация создаёт новую неизменяемую версию. Анкета сохраняет снимок вопросов и ответов, исходные анкеты не меняются при новой публикации. Повторная отправка с тем же ключом и содержимым возвращает исходную анкету, другая нагрузка — 409.

Вход: POST `/api/admin/login`, тело `{password}`. Cookie HttpOnly, SameSite Strict, срок 8 часов. GET `/api/admin/session` возвращает csrfToken; все остальные изменяющие запросы кабинета требуют заголовок `X-CSRF-Token`. Статусы анкет: `new`, `in_progress`, `reviewed`, `archived`. Фильтр по дате использует календарную дату Europe/Moscow (UTC+3). В базе время хранится в UTC.

Видео принимаются в multipart поле `video`: только MP4, до 100 МБ; проверяется заголовок контейнера, файл получает случайное имя. Видео отдаются с поддержкой Range. Проверка контейнера не заменяет перекодирование и ручную проверку файла. Объекты allowOther: single `{value:'__other__',other:'текст'}`; multiple `{values:['вариант','__other__'],other:'текст'}`. Сохранённые ответы нормализуются в строку/массив строк.

Демонстрационный режим обязателен. До сбора реальных данных необходимо согласовать тексты вопросов, согласия, обработчика, сроки хранения, условия размещения и доступ сотрудников. Для согласованного запуска можно задать `ALLOW_PRODUCTION_CONTENT=true`, затем опубликовать содержание с `demo:false`. Для reverse proxy используйте HTTPS, `SECURE_COOKIES=true` и точный `PUBLIC_ORIGIN=https://...`. Сервер слушает только loopback. Прокси должен иметь лимит загрузки не меньше 100 МБ. Персональные данные отсутствуют в логах; в SQLite они не зашифрованы — нужен защищённый сервер/диск и доступ только уполномоченным лицам.

`npm run backup` создаёт согласованную онлайн-копию SQLite и копию загрузок, оставляет последние 7 копий. Загружайте файлы перед запуском копирования или приостановите редактирование на время копии: БД согласована, дерево файлов не является атомарным снимком. Папка резервных копий также содержит ответы, её нельзя публиковать. Для восстановления остановите сервер и сохраните текущую `data` отдельно. Выполните `npm run restore -- /полный/путь/к/копии`. Скрипт не запускается при работающем сервере, объединяет текущий журнал удалений с журналом копии, удаляет отмеченные анкеты из восстанавливаемой базы, заменяет SQLite и загрузки и завершает старые сессии. После запуска проверьте кабинет и видео. Сервер также применяет журнал при старте, защищая от возврата удалённых анкет при ручной подмене SQLite. 

DELETE `/api/admin/submissions/:id` требует вход и CSRF, физически удаляет анкету из рабочей базы. Перед удалением атомарно записывает только её случайный ID в приватный `data/deleted-submissions.json` (600), чтобы восстановление старой копии не вернуло анкету. Текущий журнал нельзя удалять или заменять старым. Храните актуальную копию журнала отдельно от старых резервных копий и переносите её при миграции: потеря журнала снимает эту защиту. Старые резервные копии могут содержать ранее удалённые ответы до окончания согласованного срока их хранения; прямой доступ к ним должен быть ограничен. Сроки хранения и регламент удаления согласовываются до реального запуска.

Пароль берётся из окружения или существующего приватного файла; храните его отдельно от резервной копии.
